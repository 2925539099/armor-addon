## 内容

### 木制盔甲（材料 `armor_addon:wood`）

用**原木**合成的入门盔甲，护甲值等同皮革，但耐久只有铁盔甲的一半。

| 物品 | ID | 防御 | 耐久 |
| --- | --- | --- | --- |
| 木制头盔 | `armor_addon:wood_helmet` | 1 | 82 |
| 木制胸甲 | `armor_addon:wood_chestplate` | 3 | 120 |
| 木制护腿 | `armor_addon:wood_leggings` | 2 | 112 |
| 木制靴子 | `armor_addon:wood_boots` | 1 | 97 |

材料属性：

- 防御点：1 / 3 / 2 / 1（同皮革）
- 耐久：铁盔甲的一半（铁盔甲为 165 / 240 / 225 / 195）
- **附魔亲和度：5** —— 远低于原版最低的铁（9），因此极难附魔
- 韧性：0.0、击退抗性：0.0（同皮革）
- 修复材料：任意原木
- 穿戴音效：原版没有木制盔甲音效，使用通用的 `ARMOR_EQUIP_GENERIC`

### 羊毛盔甲（材料 `armor_addon:wool`）

防御与附魔完全对标原版皮革盔甲，但耐久翻倍，并且每件都带 2.0 韧性。

| 物品 | ID | 防御 | 耐久 |

| 羊毛胸甲 | `armor_addon:wool_chestplate` | 3 | 160 |
| 羊毛护腿 | `armor_addon:wool_leggings` | 2 | 150 |
| 羊毛靴子 | `armor_addon:wool_boots` | 1 | 130 |

与原版皮革盔甲的对照：

| 属性 | 皮革 | 羊毛盔甲 |
| --- | --- | --- |
| 防御点 | 1 / 3 / 2 / 1 | 1 / 3 / 2 / 1（相同） |
| 附魔亲和度 | 15 | 15（相同） |
| 耐久倍率 | 5 | **10（两倍）** |
| 韧性 | 0.0 | **2.0（每件）** |
| 击退抗性 | 0.0 | 0.0（相同） |
| 修复材料 | 皮革 | **羊毛（`minecraft:wool` 标签，任意颜色）** |

#### 羊毛靴子的额外特性

羊毛靴子（`armor_addon:wool_boots`）在羊毛护甲属性之外还有两个特性，**仅此一件**：

- **可以在细雪上行走** —— 与原版皮革靴子一样不会陷进细雪
  （覆盖 NeoForge 在 `Item` 上的 `canWalkOnPowderedSnow` 扩展方法，
  其默认实现只对 `minecraft:leather_boots` 返回 true）。
- **移动时不会被幽匿感测体 / 坚守者探测到** —— 屏蔽下列三种振动，
  与原版**蹲行**屏蔽的那组完全一致（`GameEventTags.IGNORE_VIBRATIONS_SNEAKING`）：

  | 振动 | 对应行为 |
  | --- | --- |
  | `STEP` | 行走 / 奔跑的脚步 |
  | `SWIM` | 游泳 |
  | `HIT_GROUND` | 跳跃落地 |

  实现方式是监听 NeoForge 的 `VanillaGameEvent` 并取消以上事件
  （钩子在 `ServerLevel#gameEvent`，取消后振动不会派发给附近监听者）。
  放置方块、攻击、交互等**其它**动作仍会正常发出振动。

### 铁制内衬甲（材料 `armor_addon:iron_lining`）

继承铁盔甲的附魔与自定义名称，并把铁盔甲已损失的耐久原样同步到新盔甲上。
本套盔甲**不参与染色**，使用单一固定材质（外壳为铁、内衬为羊毛）。

### 重型甲系列（材料 `armor_addon:iron_heavy` / `gold_heavy` / `diamond_heavy` / `alloy_heavy`）

在对应内衬甲的基础上强化的版本，**韧性、附魔亲和度均与内衬甲完全相同**，
只有护甲值和耐久提升。

| 套装 | 护甲值（头/胸/腿/靴） | 耐久 | 韧性 | 附魔亲和度 |
| --- | --- | --- | --- | --- |
| 铁制重型甲 | 4 / 9 / 7 / 4 | 297 / 432 / 405 / 351 | 2.0 | 9 |
| 金制重型甲 | 4 / 8 / 5 / 3 | 138 / 201 / 189 / 163 | 2.0 | 25 |
| 钻石重型甲 | 6 / 13 / 10 / 6 | 652 / 949 / 891 / 771 | 4.0 | 10 |
| 合金重型甲 | 6 / 13 / 10 / 6 | 732 / 1065 / 999 / 865 | 5.0 | 15 |

- 护甲值 = 对应内衬甲 **+1 / +2 / +1 / +1**（铁制、金制）或 **+2 / +4 / +3 / +2**（钻石制、合金制），按头盔 / 胸甲 / 护腿 / 靴子
- 耐久 = 对应内衬甲 **×1.5**（出现 .5 的截断取整）
- 击退抗性、穿戴音效、修复材料沿用对应内衬甲；合金重型甲同样**带抗火**
- 与内衬甲一样是**单一固定材质，不支持染色**

### 超重型甲系列（材料 `armor_addon:iron_ultra_heavy` / `gold_ultra_heavy` / `diamond_ultra_heavy` / `alloy_ultra_heavy`）

在**重型甲**基础上再强化一级，工作台合成（配方见下节）。

| 套装 | 护甲值（头/胸/腿/靴） | 耐久 | 韧性 | 击退抗性 | 附魔亲和度 | 移动速度（每件） |
| --- | --- | --- | --- | --- | --- | --- |
| 金制超重型甲 | 5 / 11 / 7 / 4 | 151 / 221 / 207 / 179 | 4.0 | 0.1 | 25 | **−7.5%** |
| 铁制超重型甲 | 6 / 13 / 10 / 6 | 326 / 475 / 445 / 386 | 4.0 | 0.1 | 9 | **−5%** |
| 钻石超重型甲 | 9 / 18 / 14 / 9 | 717 / 1043 / 980 / 848 | 6.0 | 0.1 | 10 | **−2.5%** |
| 合金超重型甲 | 9 / 18 / 14 / 9 | 805 / 1171 / 1098 / 951 | 7.0 | 0.2 | 15 | **−10%** |

- 护甲值 = 对应重型甲 **+1 / +3 / +2 / +1**（金制）、**+2 / +4 / +3 / +2**（铁制）
  或 **+3 / +5 / +4 / +3**（钻石制、合金制），按头盔 / 胸甲 / 护腿 / 靴子
- 耐久 = 对应重型甲 **×1.1**
- 韧性 = 对应重型甲 **+2.0**
- 击退抗性 = 对应重型甲 **+0.1**（合金制因此达到 0.2）
- **金制与合金制让猪灵保持中立**；合金制与重型甲一样**带抗火**
- 全部四套每件提供 **2 点**音波抗性（比羊毛系的 1 点翻倍）
- 工作台合成时会**继承基底的附魔、自定义名称与已损失的耐久**
- **重量惩罚**：穿在身上会降低移动速度，每件按上表扣减、穿满四件累加
  （金制 30%、铁制 20%、钻石 10%、合金 40%）。按基础速度计算，
  不会把迅捷药水等加成一起缩小。只作用于超重型甲，重型甲不受影响
- 自带**肩甲**与**膝盖护板**（作者用 Blockbench 单独建模，非原版形状）

结构与原版「钻石 → 下界合金」的升级完全同构。

继承行为也不需要额外代码：`SmithingTransformRecipe.assemble()` 调用
`base().transmuteCopy(result, count)`，而 `transmuteCopy` 会带上**基础装备上显式设置过的组件**
（附魔、自定义名称、已损失的耐久），但不含 `max_damage`（它来自物品原型）——
所以产物既继承了数据，又使用合金内衬甲自己的耐久上限。

两条路线并存：既可以从下界合金盔甲 + 羊毛盔甲直接做，也可以先在锻造台把钻石内衬甲升上去。

十四套盔甲都会出现在创造模式「战斗」物品栏。

### 锻造台：升级为重型甲

把**盔甲升级模板**放在模板槽、对应内衬甲放在基底槽、矿物块放在添加物槽：

| 模板 | 基底 | 添加物 | 产物 |
| --- | --- | --- | --- |
| 盔甲升级模板 | 铁制内衬甲 | 铁块 | 铁制重型甲 |
| 盔甲升级模板 | 金制内衬甲 | 金块 | 金制重型甲 |
| 盔甲升级模板 | 钻石内衬甲 | 钻石块 | 钻石重型甲 |
| 盔甲升级模板 | 钻石重型甲 | 下界合金块 | 合金重型甲 |
| 盔甲升级模板 | 合金内衬甲 | 下界合金块 | 合金重型甲 |

> **合金重型甲有两条获取路线。** 一条从「钻石重型甲」升级，一条直接从「合金内衬甲」升级，
> 这样合金内衬甲不会成为无法继续升级的死路。
>
> 注意添加物用的是**矿物块**（铁块 / 金块 / 钻石块 / 下界合金块），不是锭或粒。

### 工作台：升级为超重型甲

按下面的布局摆放（`B` = 金属块，`W` = 任意羊毛，`A` = 对应重型甲，`I` = 金属锭 / 钻石）：

```
[B] [W] [B]
[W] [A] [W]
[I] [W] [I]
```

| 产物 | 金属块 | 基底 | 金属锭 / 钻石 |
| --- | --- | --- | --- |
| 金制超重型甲 | 金块 | 金制重型甲 | 金锭 |
| 铁制超重型甲 | 铁块 | 铁制重型甲 | 铁锭 |
| 钻石超重型甲 | 钻石块 | 钻石重型甲 | 钻石 |
| 合金超重型甲 | 下界合金块 | 合金重型甲 | 下界合金锭 |

> 合金超重型甲**另有锻造台路线**：钻石超重型甲 + 下界合金块 + 盔甲升级模板，
> 与既有的「钻石重型甲 → 合金重型甲」同构。

## 音波抗性

**羊毛盔甲及其升级的护甲**穿戴时，受到音波类伤害会有减免，最低减到 0。木制盔甲不生效。

| 系列 | 每件减免 | 穿满四件 |
| --- | --- | --- |
| 羊毛盔甲、四种内衬甲、四种重型甲（共九套） | 1 点 | 4 点 |
| 四种超重型甲 | **2 点** | **8 点** |

例：普通难度下坚守者音波原本 6 点，穿满四件后为 **2 点**。

坚守者的音波伤害类型 `minecraft:sonic_boom` 属于原版 `minecraft:bypasses_armor` 标签，
护甲、盾牌、保护魔咒都挡不住，只有抗性提升有效；本机制补上了这个缺口。

减免范围由伤害类型标签 `armor_addon:sonic_like` 决定，默认只含 `minecraft:sonic_boom`。
往这个标签里追加条目即可让其他模组的同类音波伤害一并生效。
## 安装

1. 安装 Minecraft 1.21.1 的 **NeoForge**（21.1.244 或更高的 21.1.x）。
2. 从本仓库的 [`releases/`](releases/) 目录下载 jar（也可自行构建，见下节），
   放入 `.minecraft/mods/`。当前最新版本为 `盔甲附加-1.3.0.jar`。

**不需要**额外的前置模组。

## 构建

需要 **JDK 21**。

```bash
# Windows
gradlew.bat build

# Linux / macOS
./gradlew build
```

产物位于 `build/libs/盔甲附加-<版本>.jar`（文件名在 `build.gradle` 的 `base.archivesName` 里设置，版本号取自 `gradle.properties` 的 `mod_version`）。

> 本次构建使用的是工作区内的 Gradle 缓存目录 `../.gradle-home`。想复用它以免重新下载：
>
> ```powershell
> $env:GRADLE_USER_HOME = "<工作区>\.gradle-home"
> .\gradlew.bat build
> ```
>
> 不设置也可以，Gradle 会改用默认的 `~/.gradle` 并重新下载依赖。

### 关于下载源（重要）

本机网络环境下，Mojang 官方下载源与 NeoForge 官方仓库**均不可达**：

| 原始地址 | 状态 | 本项目使用的镜像 |
| --- | --- | --- |
| `libraries.minecraft.net` | 证书握手失败 | `bmclapi2.bangbang93.com/maven/` |
| `piston-meta.mojang.com` / `piston-data.mojang.com` | 证书握手失败 | 本地重写代理 → BMCLAPI |
| `resources.download.minecraft.net` | 证书握手失败 | `bmclapi2.bangbang93.com/assets/` |
| `maven.neoforged.net/mojang-meta` | 连接超时 | `neoforged.forgecdn.net/mojang-meta/` |
| `maven.neoforged.net/releases` | 连接超时 | `neoforged.forgecdn.net/releases/` |

ModDevGradle 把前三个仓库**硬编码**在插件里，因此 `gradle/mojang-mirror.gradle`
在构建时按名字把它们替换成镜像。

而 NeoForm Runtime（NFRT）会从 Minecraft 版本清单与版本 JSON **内容里**读取
client / server jar 的下载地址，这些地址无法用 Gradle 属性替换。所以该脚本还会启动
一个本地 HTTP 重写代理：把 JSON 里所有 Mojang 域名改写成 `http://127.0.0.1:<端口>/`，
再转发到 BMCLAPI，并通过 `neoFormRuntime.launcherManifestUrl` 提供给 NFRT。

- 代理使用**固定端口** `mirror_port`（默认 47821）：NFRT 会缓存改写过 URL 的版本 JSON，
  端口若每次都变，缓存里的地址就会失效导致下载失败。
- 若你的网络能直连 Mojang 与 `maven.neoforged.net`，删掉 `build.gradle` 里的
  `apply from: 'gradle/mojang-mirror.gradle'` 一行即可还原为官方源。

Gradle 发行包通过华为云镜像下载（见 `gradle/wrapper/gradle-wrapper.properties`）。

## 版本号规则

采用语义化版本 `主.次.修正`（`MAJOR.MINOR.PATCH`）：

| 位 | 何时递增 | 例子 |
| --- | --- | --- |
| **修正号** `1.0.x` | 小改动与**机制**：替换 / 重绘贴图、改文案、改简介、修 bug，以及**新增或调整游戏机制** | 新增音波抗性机制 → `1.2.1` |
| **次版本号** `1.x.0` | **新增内容**：新增盔甲套装、新增物品、新增配方 | 新增合金内衬甲 → `1.1.0` |
| **主版本号** `x.0.0` | 不兼容变更：删除已有物品 / 改名导致旧存档失效、需要新版 NeoForge | 移除整套盔甲 → `2.0.0` |

版本号写在本文件同级目录的 `gradle.properties` 的 `mod_version` 里，改完重新构建即可。
完整改动记录见 [CHANGELOG.md](CHANGELOG.md)。
