# 装饰方块的贴图布局说明

这份文档记录**超重型甲的肩甲与膝盖护板**在 `addBox` 下的贴图规则，以及为什么需要额外的处理。
这些都是实际踩过的坑，改之前请先读一遍。

---

## 一、六个面在贴图上的位置

`CubeListBuilder.texOffs(u, v).addBox(x, y, z, w, h, d)` 的 UV 是**自动布局**的，
六个面各占贴图上一块固定的矩形。记：

```
f4 = u                    f10 = v
f5 = u + d                f11 = v + d
f6 = u + d + w            f12 = v + d + h
f7 = u + d + 2w
f8 = u + 2d + w
f9 = u + 2d + 2w
```

则（数字是 `(x1, y1, x2, y2)`）：

| 面 | UV 矩形 | 展开位置 |
| --- | --- | --- |
| **WEST** | `f4, f11, f5, f12` | `(u, v+d)` ~ `(u+d, v+d+h)` |
| **NORTH** | `f5, f11, f6, f12` | `(u+d, v+d)` ~ `(u+d+w, v+d+h)` |
| **EAST** | `f6, f11, f8, f12` | `(u+d+w, v+d)` ~ `(u+2d+w, v+d+h)` |
| **SOUTH** | `f8, f11, f9, f12` | `(u+2d+w, v+d)` ~ `(u+2d+2w, v+d+h)` |
| **DOWN** | `f5, f10, f6, f11` | `(u+d, v)` ~ `(u+d+w, v+d)` |
| **UP** | `f6, f11, f7, f10` | `(u+d+w, v)` ~ `(u+d+2w, v+d)` |

**注意 `UP` 的右边界是 `u+d+2w`，不是 `u+2d+w`** —— 这点很容易抄错。

### 和 Blockbench 的差异

Blockbench 的 bbmodel 里每个面是**显式指定** UV 的，它记的列顺序与上面不同：

| 贴图上的列 | Blockbench 叫 | Minecraft 叫 |
| --- | --- | --- |
| 第 1 列 `(u, v+d)` | `east` | **WEST** |
| 第 2 列 `(u+d, v+d)` | `north` | NORTH |
| 第 3 列 `(u+d+w, v+d)` | `west` | **EAST** |
| 第 4 列 `(u+2d+w, v+d)` | `south` | SOUTH |
| 上排左 `(u+d, v)` | `up` | **DOWN** |
| 上排右 `(u+d+w, v)` | `down` | **UP** |

**左右互换、上下互换、前后不换。**

> **注意：不要为了"把名字对上"而去改贴图。**
>
> 顺着这个表很容易想到"把第 1 列和第 3 列对调"，**但那是错的** ——
> 加上 `mirror()` 之后内外侧会再交换一次，两次抵消，结果是外侧取到内衬纯色。
> 详见下一节。**贴图保持 bbmodel 原样即可。**

`tools/convert_to_addbox_layout.py` 是为旧思路写的，**现在不需要运行它**。

## 一点五、`mirror()` 会顺带交换内外侧 —— 别再手动对调贴图

这一条是踩得最深的一个坑，**单独强调**。

`mirror` 在 `ModelPart.Cube` 里做的事不止"翻转图案"：

```java
if (mirror) {
    float f3 = f;          // f 是 maxX
    f = p_272824_;         // f 变成 minX
    p_272824_ = f3;        // minX 变成 maxX
}
```

**它把立方体的 minX 和 maxX 对调了。** 而 `WEST` 面用的是顶点 `minX` 那一侧、
`EAST` 面用的是 `maxX` 那一侧 —— 于是：

> **加了 `mirror()` 之后，"内侧"和"外侧"显示的 UV 区域也互换了。**

所以**不能再手动对调贴图上的第 1/3 列**。两者会互相抵消，结果是
**外侧取到内衬那块纯色**（表现就是"外面变成一块纯色"）。

**正确组合是：贴图保持 bbmodel 原样 + 代码里加 `mirror()`**，不要改贴图。

验证方法：外侧应取到 bbmodel 的 `east`（左肩）/ `west`（右肩），也就是作者画花纹的地方。

## 二、每个面内的图案朝向

光把位置对上还不够 —— `ModelPart.Polygon` 把 4 个顶点映射到 UV 矩形的 4 个角，
顺序是固定的：

```java
vertices[0] -> (x2, y1)
vertices[1] -> (x1, y1)
vertices[2] -> (x1, y2)
vertices[3] -> (x2, y2)
```

而各面传进来的**顶点顺序**在源码里也是写死的，于是每个面的图案朝向并不一样：

| 面 | 顶点顺序 | 结果 |
| --- | --- | --- |
| WEST | `v7, v3, v6, v2` | 水平**翻转** |
| NORTH | `v, v7, v2, v1` | 不翻转 |
| EAST | `v4, v, v1, v5` | 水平**翻转** |
| SOUTH | `v3, v4, v5, v6` | 不翻转 |
| DOWN | `v4, v3, v7, v` | 不翻转 |
| UP | `v1, v2, v6, v5` | 不翻转 |

**结论：直接 `addBox` 会让图案与 Blockbench 预览不一致**，必须加
`CubeListBuilder.mirror()` 来整体镜像，才能对上。

**注意 `mirror()` 是整块镜像**，它同时作用于所有面 —— 这正好是需要的，
因为 Blockbench 的 `up`/`down` 用的是**反向的 UV 坐标**（例如
`up = [41,5,38,0]`，`x1 > x2`），那本身就是"这块要翻过来"的记录。

## 三、模型膨胀

原版盔甲层会把模型整体撑起来，好让盔甲包在皮肤外面：

```java
LayerDefinitions.OUTER_ARMOR_DEFORMATION = new CubeDeformation(1.0F);   // 外层
LayerDefinitions.INNER_ARMOR_DEFORMATION = new CubeDeformation(0.5F);   // 内层
```

**每个 `addBox` 都必须显式传这个参数。** 只给 `HumanoidModel.createMesh(deformation, 0)`
传是不够的 —— 原版 `createMesh` 里也是逐块传的。漏传的话自己加的方块不会膨胀，
肩甲会比手臂小一圈。

膨胀**不改变 UV 布局**，所以厚度可以靠它来补：膝盖护板本身 1 格厚，
膨胀 0.5 后视觉上是 2 格。**不要直接把厚度参数从 1 改成 2** —— 那会让侧面的
UV 布局整个移位，图案串到相邻面去。

## 四、隐藏原版的 `hat`

`HumanoidModel.createMesh` 除了 `head` 还会建一个 `hat`（比 head 大 0.5），
而 `HumanoidArmorLayer` 渲染头盔时会**连它一起打开**：

```java
p_117126_.setAllVisible(false);
switch (slot) {
    case HEAD -> {
        p_117126_.head.visible = true;
        p_117126_.hat.visible = true;   // 把外部的 visible=false 覆盖掉
    }
}
```

所以**没法用 `part.visible = false` 隐藏**。正确做法是在模型定义里把它换成
一个没有方块的 `PartDefinition`（名称必须保留，`HumanoidModel` 的构造要读它）。

## 五、复核工具

| 脚本 | 用途 |
| --- | --- |
| `tools/extract_uv_table.py` | 从四套 bbmodel 里读出所有装饰方块的 texOffs，并逐面检查贴图有没有画 |
| `tools/convert_to_addbox_layout.py` | 把第 1/3 列对调（贴图转换） |
| `tools/annotate_uv.py` | 生成护膝/肩甲的 UV 标注图，方便补画 |

改动贴图前先跑 `extract_uv_table.py`，它会直接告诉你哪个面是空的。
